Method

What runs every morning

A GitHub Actions job, in this order:

  1. Pulls the latest results from the official MLB Stats API (2015–2026, ~27,000 games).
  2. Scores yesterday's predictions and appends them to a permanent log — predictions are always made before games are played, so the tracker is a true out-of-sample record.
  3. Rebuilds each team's season-to-date profile from per-game logs — win/loss form, run differential, advanced stats (OPS, ERA, FIP, WHIP, Pythagorean expected win%), probable starting pitchers (shrunk season-to-date FIP, K−BB%, last-5-starts form), bullpen quality and 3-day workload fatigue, and per-park home advantage. Every feature is computed strictly as of first pitch, and a test suite fails the run if any of them stops being.
  4. Retrains five win-probability models: a FiveThirtyEight-style Elo baseline, logistic regression, XGBoost, an Elo+LR logistic stack fit in logit space on the validation season, and a Poisson–Skellam run-distribution model.
  5. Runs 10,000 Monte Carlo simulations of the remaining schedule and the full 12-team postseason bracket for playoff, pennant, and World Series odds.
  6. Fetches injury-list moves and call-ups, then publishes everything to this page.

Single MLB games sit close to coin flips — the best teams still lose 60+ times a year — so the benchmark is log loss and calibration against the Elo baseline, not raw accuracy. On the games every model has called, the fitted models land within a thousandth of a log loss of Elo and every bootstrap interval spans zero: the ML features are not adding measurable signal on top of the rating system. That is reported as the finding rather than dressed up, and the Head-to-head table is where to check it.

What is not in the model: pitch-level and Statcast detail, day-of bullpen availability, injuries, and trades.
